# Nightglide 开发计划

以 OMP fork 为主线：Nightglide = OMP + 品牌化 + 简化菜单与设置 + Glide 界面。功能行为默认沿用 OMP，只在明确决定处改默认值、文字和入口（见 [产品规范](PRODUCT_DIRECTION.md)）。每项完成都应附实际版本、测试和真实终端截图，不以计划勾选代替验收。

## 已完成

- **入口**：`./nightglide` 只运行 fork，带工作目录保护与外来 bunfig preload 防护；旧原型已删除。
- **界面架构**：inline 渲染器无法实现概念图的固定顶栏、全高侧栏和整窗背景（见 [视觉差距审计](reviews/visual-gap-audit.md)），改为自管整窗的 Glide 全屏模式，并设为默认；经典 inline 模式入口已于 2026-11-22 移除，Glide 是唯一的交互界面。
- **G1**：回看锚定、回到底部、全屏动画帧、`/copy`、布局设置（`--classic` 等入口后随品牌化移除；见 [Glide 记录](reviews/glide-spike.md)）。
- **G2**：视差云层与细光带、潜水光柱水草气泡、思考强度联动、256 色专用配色、无动效静帧（见 [G2 结果](reviews/glide-spike.md#g2-结果2026-11-21)）。未完成：真彩终端真机截图与录屏。
- **主题**：只内置 Nightglide 五套主题；`/theme <名称>` 直接切换。
- **品牌化**（2026-11-22）：窗口标题与状态栏标识 `✦`；用户可见命令名改为 `nightglide`；关闭上游更新检查与更新日志；删除经典界面入口；产品版本 v1.0 beta1。未完成：`--help`、常见报错、`/` 菜单与设置页的真实终端截图；启动警告与输入提示仍为英文。

## 设置与命令重做（S1–S5）

第 3 项只在原有菜单前面加了一层：只输入 `/` 时列出常用命令，但输入名字搜索时，93 个内置命令仍全部出现；`/more` 是按字母排的 99 行列表；`/settings` 的“常用”页是 14 项的中文副本，后面仍是 10 个英文标签页、约 458 项设置；中文文字直接写在代码里。这一阶段把它重做成一套完整、可维护的系统。原则不变：**只隐藏、不删除**，功能行为沿用 OMP，配置路径和保存方式不变。

### S2 命令清单与分层

- 用一份命令清单取代 `nightglide-menu.ts`：每个内置命令写明分层、分组（会话／模型／外观／工作／其他）、中英说明，以及若重复，并入哪个命令。
- **常用**（约 18 个）：只输入 `/` 时列出，带实时状态。**标准**（约 35 个）：输入名字可搜到，在 `/more` 中列出。**高级**（约 55 个，即重复与实验性命令，如 `/switch`、`/quit`、`/shake`、`/vibe`）：搜索和 `/more` 默认不显示，但完整输入名字仍可运行。
- 真正的同义命令（如 `/quit` 与 `/exit`）改为别名；`/switch` 与 `/model` 行为不同（只改本会话），保留为高级命令。
- `nightglide.commonCommands` 保留；新增 `nightglide.hiddenCommands`（默认值为高级层），两者都只出现在高级设置中。扩展、技能、模板命令不受分层影响，照常可搜索。
- 测试：每个内置命令都必须在清单中。上游新增命令时测试会失败，必须先决定它放在哪一层。

### S3 `/more` 重做

- 按分组显示，说明使用当前语言；默认只列常用和标准两层（约 50 个），最后一项是“显示高级命令（N）／Show advanced (N)”。
- 选中后仍把 `/命令名 ` 填入输入框；可直接输入文字过滤。

### S4 图形化设置页

`/settings` 打开 Glide 风格的全屏设置页，取代当前的“常用”标签：

- **布局**：左侧是分类栏（外观、模型、审批、通知、会话、语言、高级设置），右侧是当前分类的控件；底部一行显示按键提示。终端窄于 100 列时改为单栏：先选分类，再进入分类页。
- **控件**：开关（`● 开`／`○ 关`）、分段选择（`[ 完整 │ 减弱 │ 关闭 ]`）、等级条（思考强度）、说明卡片（审批三档各一张，写明哪些操作会询问）。键盘为 ↑↓ 选项、←→ 改值、Enter 确认、Esc 返回；Glide 已支持鼠标，点击控件也能操作。
- **外观**：主题以卡片展示，每张带主题配色色块和场景小预览；切换主题、动效时立即生效，可直接看效果，Esc 不会撤销已保存的值（与 OMP 一致，改即保存）。
- **模型**：显示当前模型和生效的思考强度，下面是“登录”“自定义提供商”“切换模型”三个入口，分别打开 `/login`、`/provider`、`/model`；不在这里罗列提供商设置。
- **高级设置**：打开 OMP 原有的标签页设置（去掉“常用”标签），标签名双语，内容不变。已失效的设置（如 `nightglide.layout`、上游更新检查）加隐藏标记，高级设置中也不显示。
- 颜色全部取自当前主题，256 色和无色（NO_COLOR）终端下有降级样式，ASCII 符号集下控件改用 ASCII 字符。

### S5 验收与收尾

- 单元测试：清单完整性、分层过滤、精确输入可运行高级命令、文本表双语完整、设置页各控件读写同一配置路径、窄屏布局。
- 真实终端截图（Ghostty 与 Terminal.app，80×24 与 120×36，中英各一套）：`/`、`/more`（含显示高级命令）、设置主页各分类、高级设置；录屏一次主题／动效实时切换。
- 更新 [项目现状](CURRENT_STATE.md)；第 3 项的旧实现（`settings-common.ts` 的常用标签）在新设置页通过验收后再移除。

### Glide 交互基线（G6 前补齐）

原计划 P0.2 中“交互 TUI 本体”的验证一直受阻，Glide 成为默认后需在 Glide 下重做：

- 在隔离目录用真实会话验证：输入与多行编辑、粘贴、长内容回看、取消（Esc / Ctrl+C）、文件与命令**审批对话框**（批准、拒绝、取消）、会话续接、**主题实时切换**、模型切换。
- 启动本地 oMLX 后验证本地模型的**流式回复与工具调用**；有云端凭据时再验证一次云端。外部服务不可用时标注受阻，不读取或输出用户密钥。
- **验收：**每项标明源码已查、自动化已测、真实终端已测或未验证，附失败和复现信息；历史结果不自动算作本轮通过。

### 模型识别（G4 信息栏）

- 模型以可辨识的图形加名称呈现；从实际会话与模型能力读取当前模型和已生效的思考强度，未知、不支持或切换中有明确表示。
- 厂商图标先确认使用权利与终端字符兼容，提供文字或简化字符替代；图标不能是唯一的状态依据。
- **验收：**切换模型、强度、主题和动效设置时显示同步，不影响流式内容；不暗示真实思考进度，不伪造模型或厂商。

### 视觉验收要求（G2–G5 通用）

- 每套最终主题都要有静态截图和**真实终端录屏**；录屏用于验证持续动效与输入不中断。
- 覆盖状态：空会话、长对话与代码、思考中、工具执行、审批或错误、信息栏展开与收起、无动效。
- 覆盖尺寸：**80×24、100×30、120×36 及宽屏**；布局可随尺寸收缩，但核心操作可用。另测 CJK、resize 和至少一套有限色配置。
- 记录终端、系统、字体、尺寸和版本；未测的终端列为待验证。截图必须来自实际运行界面，概念图只决定审美方向（细则见 [产品与设计规范](PRODUCT_DIRECTION.md) 的“视觉验收”）。

### 机器人与任务总结（G4）

- 设计与飞行/潜水一致的小型虚拟机器人，可位于侧栏；提供静态、低动效和紧凑形式。机器人反馈与真实状态关联，不扮演不存在的智能体。
- 提供随时调用的任务总结入口。先决定使用哪些真实会话、子任务、工具与文件信息，以及摘要是否需要模型调用；展示必要的上下文范围和可能的费用，避免自动额外调用或制造确定性结论。
- **验收：**正在进行、完成、失败、取消及信息缺失均有如实总结；若使用模型，测试失败、取消和权限边界；摘要不会修改原始记录或泄露凭据。

## P3：配置、路由和权限

### 3.1 设置向导

- 先读已有审查：[向导与审批](reviews/r1a-wizard-approval.md)（凭据明文存储、向导缺口、约 30 个工具的风险分级）和 [路由与快捷键](reviews/r1b-routing-keys.md)（四种路由模式的实际范围）。
- **2026-11-24 已做（第一步）**：`/login` 与向导只列账号登录；`/provider` 以 Base URL + Key 添加 OpenAI／Anthropic 兼容的提供商（Key 存凭据库，自动发现模型）；`/model` 只列可用提供商。尚未做：路由与回退的界面配置、连接失败后的编辑引导之外的完整向导。
- 参照 OMP 的设置方式，配置本地/云端提供商、Base URL、API Key、模型、自动或手动调度及回退。oMLX 等本地服务走真实协议和实际发现能力，不把占位模型当作成功。
- 支持取消、编辑、保存后重启恢复、连接失败和密钥遮掩；审查 OMP 既有凭据存储与现有配置优先级，避免破坏或覆盖用户原有设置。
- 用户在向导或设置中选择云端和自动调度范围；不新增“首次调用必须弹窗”的要求。界面应说明所选配置可能发送的上下文。
- **验收：**用隔离配置测试本地服务、模拟端点及具备授权时的真实云端；失败不破坏旧配置，日志和截图不暴露 key。

### 3.2 真实路由与多智能体配置

- 核对 manual/local/balanced/performance 的现有语义与产品需求，区分会话角色、子智能体、回退、其他工具和扩展的范围。增加手动选择与按用户配置自动调度，不暗示能保证网络物理隔离。
- 支持智能体的简洁状态及按需详细配置；优先复用 OMP 能力。准确呈现选定与实际服务模型，回退和失败不得隐瞒。
- **验收：**单测加真实主会话/子智能体路径，覆盖本地、可用云端、切换、回退和无可用模型。无云端凭据时如实标记受阻，不伪造跨模型结果。

### 3.3 审批策略

- 方案见 [P3.3 审批策略](reviews/p3.3-approval-policy.md)：不新增模式、不改判定逻辑；“全部询问／高风险询问／自动执行”对应 OMP 的 `always-ask`／`write`／`yolo`，默认改为 `write`。子智能体、headless、危险命令沿用 OMP；另加 `~/.omp` 默认受限、项目配置只能收紧审批。中文档位名随菜单简化做，审批框中文化随 G3 做。
- **验收：**在隔离目录使用真实工具验证三档下的批准、拒绝、取消、本会话允许、危险命令、`task` 和 headless 路径；检查已有显式配置不受影响。文档在代码验证前不得宣称新默认已经生效。
