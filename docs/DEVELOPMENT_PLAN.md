# Nightglide 详细开发计划

状态：2026-11-19 制定，除明确注明的现有代码外，以下任务均为**待实施**。依赖按顺序推进；同阶段中可在接口明确后拆分小任务。每项完成都应附实际版本、测试和画面证据，不以计划勾选代替验收。

## 交付原则

以现有 OMP fork 为主线，默认保留 OMP 能力；先解决入口和真实交互，再做可运行的场景样板，再扩展功能。四个首批主题、可关闭且随思考强度变化的动效、可折叠侧栏、机器人总结、配置向导、模型和审批都是目标，不代表现已完成。

## P0：恢复可信入口与基线

> **状态（2026-11-19/20，P0 三轮后）：**0.1 入口统一已实现并实测达标（`./nightglide` 只执行 fork，旧原型已于 2026-11-20 删除；双 cwd/会话归属/退出码/smoke/bunfig 防护均有真实运行证据；GATE 门禁全绿）。0.2 基线已建立（能力×证据级别矩阵见 `docs/coordination/zcode.md`；真实已测：本地对话、read/grep 工具、headless 审批硬拒、`-c` 会话续接、流式 delta、空格/CJK 目录归属；自动化已测：主题 115 项口径、路由语义）。**受阻未验证：交互 TUI 本体（输入/滚动/取消/审批 UI/主题实时切换，需真实终端）、云端调用、MCP/扩展/LSP 真实加载**——不因受阻关闭 P0，遗留项转入 P1.1 与后续轮次。

### 0.1 处理双入口

- 审查当前未提交的 `nightglide` 和 `scripts/verify-workbench.test.ts` 改动，理解原意；不要覆盖用户改动。明确保留旧原型的访问方式。
- 将默认入口统一到 OMP fork 前，比较现有源码入口、已安装入口和工作目录/预加载行为，确认调用时项目目录、参数透传、退出码及终端恢复。处理方案不得删除旧代码或用户数据。
- **验收：**从两个不同工作目录调用默认入口，确认项目目录及会话归属正确；版本、帮助、明确的真实 smoke、交互退出和无子模块/依赖错误均有可复现结果。`demo` 或 mock 不可冒充主线。

### 0.2 建立功能和测试基线

- 固定主仓、fork 版本及环境；列出当前主线可用入口、现有 OMP 核心能力与已知差异。审查现有场景、思考阶梯、五套主题、配置入口以及终端渲染架构。
- 用隔离的测试目录验证：启动、真实对话、流式输出、输入、滚动、取消、文件/命令审批、工具、会话续接与主题切换。外部服务不可用时标注受阻；不读取或输出用户密钥。
- **验收：**每项标识源码已检查、自动化已测、真实服务/终端已测或未验证；附失败和复现信息。历史报告只作为线索，不自动升级为本轮通过。

### 1.1 先验证架构

- 基于 OMP 的真实渲染路径制作最小样板：固定边缘场景、正文、输入、可收起侧栏；验证持续重绘与原生 scrollback、流式输出、粘贴、焦点、resize 的关系。
- 对比继续使用现有终端滚动和需要新视口时的功能、复杂度与上游兼容性。若无法兼容，先记录可选方案和需要负责人决定的取舍，不得截断历史或宣称已解决。
- **验收：**在至少一个真实终端录屏，展示运行中输入、长内容回看、侧栏开关、resize、退出恢复和无动效。记录待验证的其他终端。

### 1.2 飞行与潜水动态原型

- 飞行先实现俯瞰云层流动；潜水实现第一视角水流/植物。使用可运行的字符和色块，不把概念图当作精确像素目标。
- 建立暗色样板，确认视觉融合、合适的信息密度及正文对比，再制作各自亮色。四主题的语义状态、交互布局和可读性保持一致，场景本身可以明显不同。
- **验收：**四主题均有静态图和真实录屏；普通、工作中、审批/错误、侧栏展开/收起、无动效及 80×24、100×30、120×36、宽屏有证据。长期动画不能遮挡内容或阻断输入，所测环境和性能记录清楚。

### 1.3 思考强度与模型识别

- 从实际会话及模型能力读取已生效的思考强度；沿用并检查现有 effort ladder，不重复造一套不一致状态。未知、不支持或切换中有明确表示。
- 为不同强度设计递增的色块和动态层次，与主题场景融合；动效关闭后仍可识别强度。模型使用可辨识图形及名称，处理厂商标识权利和终端字符回退。
- **验收：**切换模型、强度、主题和动效设置时显示同步且不影响流式内容；不暗示真实思考进度，不伪造模型或厂商。提供各级别与无动效录屏。

## P2：工作台与虚拟 Agent
> **P2.1 状态（P2.1 续作轮更新）**：**主体完成**——三态侧栏（收起/简洁/详细，ctrl+n 循环）+真实工具进行中计数（pendingTools 实证）+窄屏自动让位（visible 谓词，80×24 隐藏/120 恢复，PTY 双向实证）+诚实规则；真实主线截图+PTY 全套。**受阻/未完成**：真实子智能体五行现场取证（omlx/endless 未实际调用 task 工具——模型遵从度，侧栏诚实显示无活动；registry 逻辑 fork 代码覆盖）、细节层 tokens（无真实子智能体可测）、主题适配（映射待决）。P2.2 排队。

### 2.1 主界面和侧栏

- 对话为默认视图；侧栏默认收起，提供明确的键盘操作与可发现入口。展开时展示当前模型、思考强度、活动智能体的真实状态；细节可展开，信息不重复堆叠。
- 保留消息、工具结果、代码、审批、焦点、快捷键、长对话及 OMP 会话操作。屏幕空间不足时先压缩装饰和可选面板，不压缩必要交互。
- **验收：**从真实会话触发工具和子智能体，验证状态的开始、结束、失败、取消与并发；操作切换不丢输入和历史；纯键盘可完成主要流程。

### 2.2 机器人与任务总结

- 设计与飞行/潜水一致的小型虚拟机器人，可位于侧栏；提供静态、低动效和紧凑形式。机器人反馈与真实状态关联，不扮演不存在的智能体。
- 提供随时调用的任务总结入口。先决定使用哪些真实会话、子任务、工具与文件信息，以及摘要是否需要模型调用；展示必要的上下文范围和可能的费用，避免自动额外调用或制造确定性结论。
- **验收：**正在进行、完成、失败、取消及信息缺失均有如实总结；若使用模型，测试失败、取消和权限边界；摘要不会修改原始记录或泄露凭据。

## P3：配置、路由和权限

### 3.1 设置向导

- 参照 OMP 的设置方式，配置本地/云端提供商、Base URL、API Key、模型、自动或手动调度及回退。oMLX 等本地服务走真实协议和实际发现能力，不把占位模型当作成功。
- 支持取消、编辑、保存后重启恢复、连接失败和密钥遮掩；审查 OMP 既有凭据存储与现有配置优先级，避免破坏或覆盖用户原有设置。
- 用户在向导或设置中选择云端和自动调度范围；不新增“首次调用必须弹窗”的要求。界面应说明所选配置可能发送的上下文。
- **验收：**用隔离配置测试本地服务、模拟端点及具备授权时的真实云端；失败不破坏旧配置，日志和截图不暴露 key。

### 3.2 真实路由与多智能体配置

- 核对 manual/local/balanced/performance 的现有语义与产品需求，区分会话角色、子智能体、回退、其他工具和扩展的范围。增加手动选择与按用户配置自动调度，不暗示能保证网络物理隔离。
- 支持智能体的简洁状态及按需详细配置；优先复用 OMP 能力。准确呈现选定与实际服务模型，回退和失败不得隐瞒。
- **验收：**单测加真实主会话/子智能体路径，覆盖本地、可用云端、切换、回退和无可用模型。无云端凭据时如实标记受阻，不伪造跨模型结果。

### 3.3 审批策略

- 设计并实现易切换的全部询问、高风险询问和自动执行；目标默认高风险询问。先依据 OMP 的实际工具、命令和权限模型列出风险分类、无法判断的操作、逐工具覆盖、已有用户配置以及 headless 行为，明确其局限并经确认。
- **验收：**在隔离目录使用真实工具验证批准、拒绝、取消、未知操作、模式切换、持久化和非交互路径；检查对已有用户的行为变化。文档在代码验证前不得宣称新默认已经生效。

## P4：兼容、发布与维护

- 在明确的支持平台和终端上检查尺寸、字体、CJK、颜色降级、无色、快捷键、异常退出及终端恢复；记录版本与结果。
- 验证安装、升级、干净环境、数据与配置兼容、fork 可获取性、许可证和第三方通知。源码 launcher 与二进制分别验收，不能把前者的结果套到后者。
- 制定上游更新流程：记录基线与 fork 改动，更新后回归入口、工具、会话、权限、配置、模型、动画和主题。
- 旧原型是否删除需单独检查引用并取得确认；历史文档保留追溯。发布时给出已知限制，不宣传未验证的“全部兼容”。

## 需要后续决策

1. 真实终端原型是否能同时满足原生 scrollback、固定场景及展开侧栏；如不能，选取具体取舍。
2. 高风险操作的详细分类、未知操作和 headless 模式的默认行为，及对既有 OMP 配置的迁移策略。
3. 机器人总结使用什么信息、何时调用模型以及如何呈现潜在费用。
4. 支持的终端/系统范围、动画性能预算、最终图标授权与具体主题色，均以测量和视觉验收确定。

这些是需要在对应阶段先解决的设计问题，不是授权跳过验证或擅自删减 OMP 能力。
