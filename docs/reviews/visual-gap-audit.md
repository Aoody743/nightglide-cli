# 视觉差距审计：概念图 vs 主线现状（2026-11-20）

对照：[飞行概念](../reference/flight-concept.png)、[潜水概念](../reference/dive-concept.png)、[主线实拍 120×36](visual-gap-mainline-120x36.png)（`./nightglide`，`NIGHTGLIDE_SIDEBAR=open`，Terminal.app 默认浅色配置，fork 工作区未提交版本 `558af61917+dirty`）。

## 结论

差距的根源是**布局架构**，不是配色或字符细节。概念图是一个**占满窗口的应用**：顶栏、上下场景带、带边框的对话卡片、贯穿全高的右侧信息栏、底部输入卡片，所有格子都有主题背景色。主线是 OMP 的 **inline 渲染器**：已完成的内容直接打印进终端原生 scrollback，只有底部一小块“可变视口”能重绘。在这个模型下：

| 概念图元素 | inline 模式能否实现 | 原因 |
|---|---|---|
| 顶部场景带、固定顶栏 | 不能 | 固定顶部区域需要 DECSTBM，会丢 scrollback（此前已三方验证） |
| 贯穿全高的右侧栏 | 不能 | 历史行已打印出去，无法在旁边再画一列；现在只能贴在可变视口的头几行 |
| 对话包在边框卡片里 | 不能（对历史部分） | 卡片边框要跟随滚动重绘 |
| 整窗主题背景 | 不能可靠实现 | 历史行一旦打印就不再受控；终端是浅色配置时暗主题直接“穿帮”（见实拍：暗色 flight 主题画在白底上） |
| 底部场景带 + 输入卡片 | 可以 | 已部分实现（3 行场景） |

此前各轮已经正确识别了这个约束（`docs/coordination/zcode.md` “架构取舍记录”），但选择了**保留 inline、把场景降级为底部 Ambient Dock**。这个选择保住了原生 scrollback，代价就是界面永远不可能接近概念图。后续十余轮在这个框架内打磨、取证、写门禁，所以投入很多、画面变化很小。

## 实拍中可见的具体问题

1. **背景**：主题不画背景，完全依赖用户终端底色。浅色终端上的暗主题文字对比失效，场景色块浮在白底上。
2. **场景**：只有 3 行，只用前景色字符（`▀ █ ░ ·`），读起来像棋盘格；概念图是 5–8 行、上下各一条、有明暗渐变的密集像素云/水草。
3. **侧栏**：是一个 4 行小框，按行号拼接到可变视口的第 0 行，所以压在欢迎区/顶栏右侧；右边框被截断（`#withSidebar` 用 `truncateToWidth(w-1)` 与边框宽度不一致）。内容只有“模型/强度/智能体”三行文字，没有概念图里的分节标题、强度条、智能体状态色、Status 区。
4. **对话区**：仍是 OMP 原样的消息与工具渲染；没有“you”卡片、Nightglide 回复区、工具 chip 行、带标题栏的 diff 卡片。
5. **机器人形象**：不存在（只有工作台样板里一行 `ng-bot` 文字）。
6. **思考强度**：只有单个 ladder 字符，没有概念图里的分段彩条。
7. **欢迎区**：OMP 大字 logo + Tip 文案（仍提到 `omp`），与概念图的极简顶栏风格冲突。
8. **主题**：五套主题对四套目标的映射未定；亮色主题从未在真实终端验收。

## 过程问题

- 同时存在四条视觉实现线：旧 OpenTUI 原型（`apps/cli`）、工作台样板（`scripts/p1-zcode/workbench`）、Antigravity 样板（`scripts/p1-prototype`）、fork 主线。样板的场景并没有完整进入产品。
- 大量精力用在门禁、证据目录和文档状态上（`CURRENT_STATE.md` 一段话里塞了十几轮结论），而判断“像不像概念图”的标准从未写成可对照的检查表。
- 主仓与 fork 都有大量未提交改动（fork 5 改 6 增；主仓 9 改 12 增），干净检出看不到任何本轮成果，丢失风险高。

## 推荐路线

### 决策（需负责人拍板）：增加全屏 “Glide 模式”，作为默认界面

在 alt-screen 中由 Nightglide 自己管理整窗布局，对话历史放进应用内滚动视口；保留现有 inline 模式作为 `--classic`（或设置项），给需要原生 scrollback / 终端搜索 / tmux 复制的用户。

- **得到**：概念图里所有元素都可实现；整窗背景可控，不再依赖终端底色。
- **失去（Glide 模式下）**：终端原生 scrollback 与原生搜索。须补上应用内滚动（PgUp/PgDn、鼠标滚轮、回到底部）、`/` 搜索、复制模式（或鼠标选择时临时关闭鼠标上报）、退出后把会话摘要打印回主屏。
- **可行性**：fork 已有全部底层件——`tui.ts` 的 fullscreen overlay alt-buffer 管理（进入/退出/恢复/鼠标）、`components/scroll-view.ts` + `scroll-viewport.ts`（滚动条、对齐、跟随）、`composer.ts` 的 `#renderResizeTail`（按宽度重渲染整段 transcript）。不需要换框架。

如果负责人坚持只用 inline，应当明确接受“界面只能做到底部场景 + 底部信息条”，并据此修改产品规范，而不是继续拿概念图做验收。

### 分阶段实施（Glide 模式）

**G1 外壳布局（先只做飞行暗）**
- 新增 `NightglideShell`（fullscreen 根组件）：顶栏 1 行（✦ Nightglide ··· 规则线 ··· `[ FLIGHT DARK ]`）、顶部场景带、主体（左：对话视口；右：信息栏，宽 ≥120 列时显示，否则收起）、输入卡片 3 行、底部场景带。高度不足时先砍场景带，再砍侧栏。
- 每个格子都写主题背景色（新增 `pageBg` / `cardBg` / `panelBg` 槽位，schema 里已有 `background` 描述可复用）。
- 对话视口复用现有 transcript 渲染，先不改消息样式；做好跟随尾部、手动回看不被拉回、resize。
- 验收：与 `flight-concept.png` 左半边并排截图，整体结构一致。

**G2 场景渲染升级**
- 改用上半块 `▀` + 前景/背景双色，垂直分辨率翻倍；每主题 4–6 级渐变色板 + 有序抖动；上带云层向下看、下带云底；潜水为水面光带 + 水草/珊瑚剪影 + 气泡粒子。
- 动画 8–12 fps 节流，只重绘场景区域；`--motion none` 静态帧。
- 将 `scripts/p1-zcode/workbench` 中已调好的场景算法合并进 fork，之后删除样板的重复实现。

**G3 内容卡片**
- 用户消息卡（`> you` + 正文）、助手区（机器人头像 + `✦ Nightglide` + 强度条 + 正文）、工具 chip 行（`[✎ edit] [⚗ test] [⌕ search]`，来自真实工具调用）、diff 卡片（文件名标题栏 + `diff` 标签 + 行号 + 增删底色）。
- 全部以 OMP 现有组件为基础换皮，不改行为。

**G4 信息栏 + 机器人**
- 分节：Model（图标 + 名称）、Effort（分段彩条 + 档位文字，未知时显示“未知”）、Agents（真实子智能体，状态色）、Status（思考中/工具中/空闲，来自真实事件）。
- 机器人：约 10×5 格半块像素精灵，飞行/潜水两套造型 × 亮暗两套配色；空闲/思考/完成三帧；空间不足时缩成 1 行图标。

**G5 四主题与亮色**
- 定映射（建议：flight / cloudlight / abyss / daybreak，aurora 保留为额外主题），亮色单独调对比度；四主题 × 空会话/长对话/思考中/工具/审批/错误/无动效 截图对照。

**G6 Glide 模式补齐 inline 失去的能力**
- 应用内搜索、复制模式、退出时回写摘要、`--classic` 开关与设置项、窄屏（80×24）降级。
