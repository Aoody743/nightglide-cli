# Nightglide · 终端体验方向

本文件是新主线的设计方向，不表示界面已经实现。旧 `DESIGN_SYSTEM.md` 和 `MOTION_SYSTEM.md` 保留为灵感与主题参考，其中 OpenTUI 技术方案、完成度与性能数字不再作为新主线的事实。

## 想要达到的体验

用户在终端里长时间与编码助手一起工作：输入指令、读回答、审阅代码变更、查看工具和子任务、处理错误。界面应当有高完成度和辨识度，让人一眼感到 Nightglide 的深空、光线与速度，同时让正文、代码和用户的下一步操作始终清楚。

**华丽来自完成度：**深邃而有层次的色彩、精确对齐的排版、不同状态的细腻变化、恰到好处的动态反馈，以及宽屏与窄屏都成立的构图。不要以大面积 ASCII 装饰、满屏边框、密集标签或长篇飞行隐喻代替设计。

## 工作台

1. **对话是主角。** 上下文和状态收敛在轻量界面边缘；大部分面积留给用户消息、回复和代码。对话可连续滚动，长内容不被挤没。
2. **输入始终可信。** 多行输入、选择、编辑、粘贴、发送和取消沿用可靠的原生行为；焦点、忙碌、可取消和错误状态一眼可辨。
3. **工具融入时间轴。** 正在做什么、完成了什么、是否需要用户决定，靠层级和真实内容表达；详情按需展开。审批和差异视图保留完整操作能力。
4. **状态有来源。** 当前模型、连接、工具和子任务只显示真实状态。模拟内容只能出现在明确标注的演示中。
5. **色彩有节奏。** 深夜的深蓝与低饱和蓝紫作为基础，明亮的冰蓝或极光色只用于焦点、进行中和重要变化；成功、警告、错误各自可区分，也有文字说明。其他三套主题用相同语义层级重作，不只是换背景色。
6. **动效回应动作。** 使用有限字符帧呈现思考、工具执行和交接的状态变化，稳定占位、不抢占输入；低动效模式立即呈现静态状态。

## 首屏构图草案

以下只说明层级，不是最终视觉成品。顶部是一条安静的导航线；对话自然流动；底部输入器是页面中最明确的操作锚点。光感来自颜色和密度的变化，不在正文周围叠框。

```text
  ✦ nightglide                                  project  /  model
  ────────────────────────────────────────────────────────────────

  你  帮我检查登录流程，并解释发现的问题。

  ✦   我会先追踪登录请求，再检查错误处理与会话状态。

      ↳ 读取  src/auth/session.ts                 已完成
      ↳ 搜索  login / refresh token                正在进行

      发现两处需要关注：
      1. 令牌过期时，界面没有保留用户正在填写的内容……

  ────────────────────────────────────────────────────────────────
  ❯ 继续追问，或输入下一步任务
                                              ↵ 发送    esc 取消
```

视觉制作需交付三类状态的真实终端画面：**静态阅读**展示文字和代码的节奏；**工作中**展示可识别但不跳动的工具状态；**需要决定**突出审批和差异内容。最终表现应比草图更精致，以可运行界面的色彩、对齐、留白、动效和交互反馈来证明。

## 空间与尺寸

| 终端 | 优先级 | 设计要求 |
|---|---|---|
| 80×24 | 核心对话 | 紧凑头尾，保留输入及可滚动正文；面板按需展开。 |
| 100×30 | 日常基准 | 稳定的消息阅读宽度、清楚的工具摘要与模型状态。 |
| 120×36 及以上 | 扩展信息 | 有足够空间时再展开上下文、子任务或差异视图，不挤压正文。 |

以上是布局验收目标，不能靠固定截取最近几条消息来冒充滚动。检查中文与中英文混排、超长路径、代码块、终端缩放以及有限颜色环境。

## 第一批实际验收画面

- 首次启动与未配置模型；真实连接状态和可操作的配置入口。
- 对话中输入多行代码、流式长回复和向上查看历史。
- 文件读取、代码修改审批与差异预览。
- 运行中的子智能体、取消、失败与恢复。
- 四主题及紧凑和宽屏尺寸；动效关闭状态。

每个画面都要使用真实控件和合理长度的内容，在终端中截图或录制后审查。细节不足时继续调整，不把设计文档当成完成的界面。
